# Contributing to Coolest Open Source Projects

Thank you for your interest in contributing! This repository is built as an educational launchpad and reference guide for **Junior Developers, Freshers, and Software Engineers** looking to understand how production-grade systems are architected and deployed.

---

## 🎯 Curation Criteria

Before submitting a pull request to add a new project, ensure it meets the following standards:

1. **Active & High Quality**: The repository must be actively maintained, have clear documentation, and a functioning build setup.
2. **Open Source License**: Must be licensed under an OSI-approved open source license (MIT, Apache-2.0, AGPL-3.0, BSD, GPL, etc.).
3. **Educational / Architectural Value**: The project must demonstrate real-world patterns that junior developers can learn from (e.g. modular structure, clean API layers, test suites, CI/CD, Docker configurations).
4. **Originality**: Provide an original, succinct description highlighting *what the system does* and *why developers should study its architecture*. Do not copy-paste marketing text directly from landing pages.

---

## 📝 Submission Format

Add your suggestion to the appropriate section in `README.md` using the standard table or card format:

```markdown
| Project | Primary Stack | Core Focus | Why Junior Devs Should Study It |
| :--- | :--- | :--- | :--- |
| **[Project Name](https://github.com/org/repo)** | `Tech1`, `Tech2` | Short one-line summary of what it does | Specific architectural pattern, codebase clarity, or system design insight |
```

### Pull Request Checklist

- [ ] Project link points directly to the GitHub repository.
- [ ] Added to the most relevant domain section.
- [ ] Tech stack tags reflect primary languages and databases used.
- [ ] "Why Junior Devs Should Study It" highlights an architectural, structural, or code-reading takeaway.
- [ ] Links and markdown formatting have been verified.
